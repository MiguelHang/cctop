# Plugin

Code: `cornercase-plugin.toml`, `cctop open`

- **One global place**: plugins cannot draw inside cornercase's UI and every tab lives in a workspace, so the global view is a project of its own, **cctop**, whose folder is the plugin's state folder (`CORNERCASE_PLUGIN_STATE`). The action `cctop` (in every context: project, workspace, tab, pane) runs `cctop open`: `cornercase open <state folder> --focus` finds or opens that project, and a tab running `cctop` is added only when none of its tabs runs it already. Closing the project is fine: the action makes it again. A panel inside cornercase was left for the core.
- **Finding the existing tab**: after `open`, `status --json` is read and the project is the one whose id `open` printed or, failing that, whose path (both canonicalised) is the state folder, also canonicalised (`cctop open` creates the folder first so it can be canonicalised). A tab runs cctop when one of its panes reports `program` `cctop` (its file name, so a full path counts too); only when no pane of the tab reports a program does the tab's name `cctop` decide. No process is read: the action must stay instant and the pane's foreground program is what cornercase already knows. A tab named `cctop` whose pane is back at its shell does not count, so the action adds a fresh tab rather than focusing a dead one: a plugin cannot type into a pane without `send`. Every workspace of the project is searched; a new tab goes in the first workspace and its pane is focused, since `new-tab` may open it in the background. The tab runs `std::env::current_exe()`, which is the same for `[[build]]` and `[download]`. Outside cornercase (`CORNERCASE_PLUGIN_STATE` unset or empty) `cctop open` fails saying so; a project that `status` does not list after `open` is an error, not a retry.
- **Services**: `[[service]] watch` runs `cctop watch` (alerts). The TUI is not a `[[window]]` process: those have no terminal.
- **Distribution**: `[download.<target>]` archives for `x86_64`/`aarch64` Linux and macOS with their sha256, built by a release workflow; `[[build]] cargo build --release` as the fallback. Published with the `cornercase-plugin` topic.
- **Permissions** declared: `read` (status), `send` is not needed; `notify` and `open` are listed so the preview is honest.
