# Processes

Code: `procs/`

- **The memory metric is cornercase's** (`design/memory.md` there): memory a process holds on its own. Linux: `RssAnon + VmSwap` from `/proc/<pid>/status`. macOS: `ri_phys_footprint` from `proc_pid_rusage` (Activity Monitor's Memory). Neither counts file-backed pages shared by every process (the binary, its libraries), so the sum over a tree is close to what it costs. RSS was rejected: cornercase measured it at about twice the real cost for Claude Code (its 224 MB binary counted once per process). For the same reason `sysinfo` is not the source: it reports RSS.
- **CPU %** is the change in user + system time between two samples divided by the wall time between them, per process (100 % = one core, as `top`). The first sample shows no CPU.
- **Environment**: Linux reads `/proc/<pid>/environ` (only the user's own processes are readable, which are the ones that matter). macOS reads `sysctl` `KERN_PROCARGS2`, which holds the arguments then the environment. Only `CORNERCASE_PANE`, `CORNERCASE_SERVER` and `CLAUDE_CONFIG_DIR` are kept.
- **One sample** lists every process of the user once (pid, parent, name, arguments, memory, CPU time, the kept variables). Processes of other users are skipped. A process that ends while being read is dropped, never an error.
- **Tests** of the real sources run on the test process: its pid is listed, a variable it set in a child is read back, and memory written to an anonymous mapping of 64 MiB raises the figure while a mapped file does not (the check cornercase uses). The memory check measures the whole test process, so it reruns itself alone in a child test process (`--exact --ignored`, gated by `CCTOP_MEMORY_PROBE`): other tests allocating in parallel threads would make it flaky.
- **A reused pid** is told apart by the process's start time (`stat` field 22 on Linux), kept in `Process::started` as an opaque value only compared for equality. If the start time differs, or the CPU time went down, the process shows no CPU for that sample instead of a wrong figure.
- **Linux fields**: parent and owner come from `status` (`PPid`, the real `Uid`); the process group, user + system time and start time from `stat`, converted with `sysconf(_SC_CLK_TCK)` (100 if it fails). The name is the one in `stat`, taken between the first `(` and the last `)` because it may hold spaces and parentheses; it is the same text as `comm`, so `comm` is not read again. A process without `RssAnon` (kernel threads, zombies) has no memory (`—`); `status` and `stat` are read as bytes and decoded lossily, because a process may set any bytes as its name (`prctl(PR_SET_NAME)`) and must not vanish from the sample for it; one whose `status` or `stat` cannot be read or parsed is dropped; missing `cmdline` or `environ` leave the arguments empty and the variables unset. Empty variables count as unset.
- **`libc`** gives `getuid` and `sysconf` (and, on macOS, `proc_pid_rusage` and `sysctl`). `rustix` was rejected: it covers Linux well but not the macOS calls, so it would mean two crates for the same job. The `unsafe` calls are sound without further checks: `getuid` and `sysconf` have no preconditions; in the tests, `mmap` is checked against `MAP_FAILED` and every access stays within the mapped length.
